# Docker 管理

FlowHub schema 2 独立插件。第一版面向本机 Docker：按 Compose 标签归组已有容器，搜索名称、镜像及项目，查看运行状态、健康检查、CPU/内存、端口和挂载信息，读取最近日志，并确认后启动、停止或重启单个容器。

## 构建与加载

在本目录运行 `npm run build`。在 FlowHub「插件市场 → 安装开发目录」选择本目录，确认安装后打开侧栏「Docker 管理」。前端修改后切换页面即可重新读取资源，后端修改后重新构建，再在「已安装」中重新加载。

Docker CLI 查找 `/opt/homebrew/bin/docker`、`/usr/local/bin/docker` 以及 Docker Desktop 自带路径。使用 Docker 当前 context，但仅接受 Unix socket 本机环境；不切换用户 context，不启动引擎，不执行 shell，不读取容器环境变量。Docker Desktop 或 Colima 必须先启动。环境变量 DOCKER_HOST / DOCKER_CONTEXT 不覆盖 context 配置。

## 行为与范围

- 容器列表可手动刷新，可见时每 15 秒更新。选中时采集详情，资源数据是单次快照。
- 日志最近 300 行，stdout 和 stderr 各限制 512 KiB，分别拼接而非严格按时间合并；可过滤和每 3 秒轮询，不是流式终端。日志只在当前页面内存中，不存盘。
- 启停重启均要求确认，核对完整容器 ID 与当前 context，环境发生变化时要求重新刷新确认。停止和重启给容器 10 秒退出时间。
- 单次 CLI 调用最长 45 秒；超时只取消本地 CLI，Docker 引擎内操作可能继续，需要刷新核实。
- 连接失败保留上次列表并显示错误、禁止操作。暂停、移除中、dead 等状态不提供不适用的操作。
- 页面支持切换浅色/深色外观和窄窗口；嵌入 FlowHub 默认深色，浏览器预览初始跟随系统。剪贴板不可用时显示命令供手动复制。
- 主页面提供「通用设置」：刷新频率、打开时默认范围、默认只看异常、Compose 默认展开和主题策略保存在插件本地；详情、日志、镜像和操作页继续保持原有能力。悬浮窗配置仍按组件单独保存，避免主页面偏好覆盖不同卡片。
- 支持「全部 / Compose / 独立容器 / 镜像」切换与搜索。Compose 分组可展开收起，刷新保留当前展开状态；点击项目进入成员详情，点击成员进入容器资源与日志页。
- 删除容器需确认完整 ID 与 context，且只接受已停止、未启动或 dead 容器。使用不带 force/volumes 的 `docker container rm`，保留数据卷和镜像；可写层和容器日志会永久删除。
- 镜像支持本地列表、搜索、大小/平台/创建时间/标签/摘要与引用容器详情。删除当前标签需确认；有容器引用（包括已停止容器及派生镜像容器）时拒绝删除。按标签移除，最后一个引用删除时镜像也移除；不强制删除、不清理父镜像。
- 目前不提供 Compose 文件编辑、compose up/build/down、项目批量启动、镜像拉取/构建/推送、远程 Docker 或数据卷删除。支持按 Compose 标签批量停止已有项目容器。

## 桌面悬浮窗

Docker 页面右上角「桌面悬浮窗」打开 FlowHub 桌面组件画布，首次会添加一张 Docker 卡片。也可从「插件市场 → 桌面组件 → 添加组件」选择 Docker。右键卡片编辑显示范围（全部、单个 Compose 项目或独立容器），可选择列表只显示异常；卡片仍显示该范围的运行总数、停止/暂停数和异常数。

支持宿主的拖动、缩放、置顶和布局保存。悬浮窗直接展示按项目分组的容器列表，每行有「停止」，Compose 分组有「停止全部」。顶部拖动条可拖动、右键编辑或点击打开详情；列表区域可滚动和操作。默认 384×360，已有小卡片至少扩至 320×280。

停止前通过 `stop_preview` 读取当前目标，确认框列出全部目标容器。`stop_confirm` 核对 Docker context、完整容器 ID 集合及当前状态；目标变化则要求重新确认。项目停止按 Compose 项目标签精确匹配，不依赖原始 YAML 路径，不执行 compose down，不删除容器、网络或数据卷。单次最多 128 个目标，批量调用 Docker stop，随后逐个查询状态；部分失败或结果无法读取会明确报告，已停止的容器跳过。日志和启动操作仍在完整管理页。

插件进程启动后每 15 秒采集一次轻量容器列表。`status_snapshot` 和 `widget_api` 的 `snapshot` 动作只读缓存；操作接口要求用户确认。采集和停止/删除后的回读互斥，避免旧采集覆盖操作后的结果。悬浮卡片每 5 秒读取缓存；60 秒未更新标记过期，连接失败不把空列表显示为正常。详情页复用完整管理界面，每 15 秒刷新真实列表。停止的容器不会被自动当成故障，重启中、dead 或健康检查失败才计入异常。插件停用或 FlowHub 退出会结束采集，桌面展示由宿主恢复。

交互式卡片需要更新支持 `widget.interactive` 和对象选择导航的 FlowHub 宿主。点击容器名直接进入该容器详情；点击 Compose 项目名进入其成员页，左侧箭头只展开收起。顶部可切换全部/Compose/独立容器，「镜像」直接打开镜像管理。「配置」可调整标题、类型、项目范围和异常筛选。导航携带对象 ID/项目名及 Docker context；环境改变后不沿用旧选择。停止按钮不会触发跳转，确认和执行期间也不会导航。宿主定时更新保留 iframe。浏览器预览禁用所有修改操作。

## 验证

`npm test`：参数校验、拒绝未确认操作、JSON 行解析、输出限制、状态摘要与组件只读接口、项目筛选、过期判定及 JS 语法。

`npm run dev`：打开 `http://127.0.0.1:5184`，仅模拟数据，不暴露 Docker 或宿主接口。

`node scripts/compose-smoke.mjs`：使用已有的 minio/minio:latest 镜像创建独立双容器 Compose 项目，验证单个停止、整个项目停止和目标变化拒绝，最后自动清理测试项目。测试容器不挂载宿主目录、不开放网络，不操作已有业务项目。

`node scripts/management-smoke.mjs`：导入独立空镜像、创建测试容器及测试卷，通过真实 widget RPC 验证对象详情、未确认/环境变化拒绝、容器删除后数据卷保留、被引用镜像拒绝删除，以及多标签逐个删除。自动清理专用测试资源，不下载或改动业务镜像。

真实冒烟测试：先创建专用容器，名称以 `flowhub-docker-smoke-` 开头、项目标签为 `flowhub-plugin-test`，日志包含 `FLOWHUB_PLUGIN_SMOKE_READY`，然后运行 `node scripts/smoke.mjs <完整容器ID>`。脚本会对该测试容器执行 restart/stop/start，拒绝测试普通业务容器。测试后需清理专用容器。
