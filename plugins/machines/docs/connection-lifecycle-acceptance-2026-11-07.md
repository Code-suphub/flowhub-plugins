## 实际断开与重连

| 步骤 | 结果与证据 |
| --- | --- |
| 建立 A 会话 | `bastionStart` 后状态进入 `ready`，`connected=true`；操作系统读到通向 62576 的真实 ESTABLISHED 连接。 |
| 执行端点查询 | `printf` 返回 `ENDPOINT=A`，退出码 0，成功任务保存到独立执行历史。 |
| 真正断开 | `bastionStop` 返回 `connected=false`、`phase=disconnected`、`paused=true`；62576 的 ESTABLISHED 连接全部消失，服务仍在监听。 |
| 断开状态保持 | 等待 3 秒后重新读取，仍为已断开且已暂停，TCP 连接仍为零。测试监控关闭，不把此步骤当成启用监控后的长时间自动重连验收。 |
| 显式重连 | 再次连接 A，出现不同客户端 PID／临时端口的新连接；查询再次返回 `ENDPOINT=A`、退出码 0。 |

结论：实际终止共享 SSH 会话、暂停状态以及显式重连的发布后端路径通过。此前原生界面的“断开确认 → 取消”已验证；本次没有把 RPC 的真实断开记成原生确认按钮点击通过。

## 连接变更与旧目标保护

在 A 的共享会话保持在线时，通过 `sshRead` 读取最新保存版本，再调用 `sshSave` 将同一别名的端口从 62576 改为 62577。仅修改独立测试配置，不改真实机器身份。

| 步骤 | 结果与证据 |
| --- | --- |
| 保存与读回 | 保存成功；重新读取端口为 62577，机器目标版本从 A 变为 B。 |
| 拒绝旧审阅版本 | 带 A 目标版本提交新命令时，RPC 明确拒绝“机器连接配置在审阅后发生变化，请刷新并重新选择目标”。该任务没有进入历史；最终 4 条测试记录均不包含其 ID。 |
| 拒绝旧在线会话 | 配置已经是 B，A 的旧会话仍在线；读取会话状态提示“连接配置已变化，请断开旧会话后重新连接”。用 B 的新版本执行查询也不能复用旧 A 会话：任务如实失败，标准输出为空，错误说明相同。 |
| 清理旧版本会话 | `bastionStop` 仍能终止旧 A 会话，不因版本不匹配而拒绝清理；A 的 TCP 连接归零。 |
| 连接新端点 | 显式启动 B 后进入 `ready`，真实连接通向 62577；查询仅返回 `ENDPOINT=B`、退出码 0，A 无遗留连接。 |
| 独立历史读回 | 共 4 条：A 查询成功、A 重连查询成功、变更后未重连的受控失败、B 查询成功；未出现被前置版本校验拒绝的任务记录。 |

结论：发布后端的保存版本、执行前版本校验、旧会话拒绝、旧会话清理和新端点重连均通过。配置改变后需要明确断开旧共享会话再连接；不会悄悄把旧连接当作新目标执行。

原生连接编辑器的保存按钮、保存后工作区刷新／草稿隔离和报错后断开入口未在本轮完整点击验证，继续保留待验；不以本轮 RPC 结果替代。独立非共享 SSH 的分离输出、非共享堡垒机分支及历史读取失败重试也仍在原清单中。

## 快捷键说明

tmux 脱离顺序是 **按 Ctrl+B，松开 Ctrl 和 B，再单独按 D**。这解除本地附着，后台共享会话继续保留。**Ctrl+D** 是另一组按键，可能向远端 Shell 发送 EOF 并使其退出；不应作为脱离步骤。

此前用户直接关闭终端窗口后，已读回本地附着解除、共享连接保留，之后查询成功。本轮没有访问被 Computer Use 禁止的 Terminal，也没有换用其他桌面工具绕过该限制。
