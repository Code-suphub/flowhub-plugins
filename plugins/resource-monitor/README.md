# 应用资源监控

FlowHub schema 2 独立原生插件，支持 macOS Apple Silicon / Intel。显示应用占用排行、固定顺序的进程详情弹窗，以及 Arc 标签进程、Codex 对话工作进程的关联，并在确认后手动结束进程。默认使用当前用户权限；可选的完整进程监控会通过 macOS 管理员认证安装以 root 运行的只读采集服务，读取 PID、名称、路径、UID、父进程、RSS、内存足迹和 CPU 时间，不读取完整命令行或环境变量，也不提供结束进程能力。用户可在插件页面点击「管理员授权安装」，通过系统认证窗口授权；服务在重启后继续运行，可从同一页面停用并卸载。授权密码由 macOS 处理，FlowHub 不接收或保存密码。该安装方式支持本地 ad-hoc 签名构建，无需付费开发者会员；对外分发应用的 Gatekeeper 签名、公证要求独立于管理员授权。Arc 标题读取和跳转需要系统自动化授权；可选的任务管理器读取需要用户在系统设置中允许 FlowHub 辅助功能权限，插件不会自动授予权限。

## 构建与安装

```sh
pnpm install --frozen-lockfile
pnpm run build
```

在 FlowHub「插件市场 → 安装开发目录」选择本插件的 **`build/`**。启用后侧栏出现「应用资源监控」，宿主通过 `statusSurface` 自动接入菜单栏状态；主页面「桌面与菜单栏」打开组件画布。也可在画布添加「应用资源监控」卡片。卡片默认显示完整应用与工具列表，在卡片内部连续滚动；标题、内存概况和更新时间固定显示。支持按内存/CPU 排序、关注单个应用，或在编辑器显式切换为仅显示前 3–10 项，点击应用进入对应进程详情。卡片内不直接执行清理。

源码位于独立的 flowhub-plugins 仓库。采集和界面修改可单独构建插件；应用名称与图标需要支持 `application_metadata` 的新版宿主，旧版宿主降级显示原名与首字母。使用 React + TypeScript + Ant Design + Tailwind v4；复用 `@flowhub/plugin-common/react` 的基础控件和 `common-components` 的 antd 主题配置。`StyleProvider layer` 与 `theme, base, antd, components, utilities` 保持样式顺序。构建产物为自包含包，不依赖源码路径、CDN 或内联脚本。

卡片使用独立的 `card.js` / `card.css` 入口，不加载管理页、编辑器或 Ant Design；其他页面继续使用 `monitor.js`。构建会分别生成自包含 IIFE，预览与正式包选择相应入口。应用元数据按路径去重，暂时失败、缺项或空图标共享最多 4 次请求预算，按 1/2/4 秒退避；明确不支持的旧宿主只探测一次，卸载和 API 切换会清理重试并丢弃旧响应。

详情区分应用的「正常退出」与进程的「结束此实例」。模拟器等独立程序可直接预览单个实例的结束目标；多个实例必须先选择，已退出的选择不会自动切换到另一个实例。一个「运行实例」表示一次独立启动形成的主进程与辅助进程集合，后台服务可能单独列出。只有原生接口支持正常退出的应用才显示正常退出入口；只有支持关联的 Arc、Codex 才分别显示「标签页」「对话与任务」，能力检查不读取标题、对话或请求自动化权限。

## 数据与来源

- 在原有归组与实例计算完成后，补充独立的显示信息：同用户 `launchctl list` 的当前服务 PID、Colima 的管理/虚拟机/网络 PID 文件、核实父链和 Android SDK 组件路径。可显示 Mycelia、toolkit SSH 网络服务、MySQL 启动脚本、Colima 实例和模拟器崩溃报告等名称。记录匹配完整进程身份；PID 文件还需核对运行程序和写入时间，过期记录不使用。采集命令限时、限量，失败保留原名。
- 显示信息不改写分组 ID、包路径、进程身份、实例、保护状态、退出目标或结束范围。项目可显示 ChatGPT 等来源；同一项目由不同应用启动时，每个实例保留自己的来源，合计只列多个来源、不猜单一归属。路径不可读取的 tmux 可通过内核启动路径或映射文件补全来源提示，仍保持保护，SSH 实例不因此重组。卡片仅包含显示名和来源摘要；详细服务登记标识只在详情与搜索中使用。

- 包外独立辅助应用仅在 bundle ID 为主应用的完整子标识、签名团队相同且主应用安装位置唯一时显示关联产品，如「QQ · QQUpdate」。关联产品名称和图标只用于展示，不替换该辅助应用的包路径、统计分组、实例和退出目标。名字相似、同一厂商或同一签名团队本身均不足以关联；无法核实的保持独立。

- Rust 通过 macOS libproc 每 5 秒采样一次，界面不可见时停止页面轮询；后台采样供菜单栏和卡片共用。宿主每 15 秒读取状态缓存，卡片每 5 秒读取缓存，不触发额外采集。插件停用/宿主退出后采集进程结束。
- 采样和动作在原生主线程串行执行，只读请求使用独立发布的不可变缓存；慢采集不持有读取锁。可选服务识别共享 800 ms 预算，超时保留原名，迟到结果不会应用到下一次采样。管理页通过 `ranking_snapshot` 读取摘要，打开详情后才用 `group_detail` 读取所选分组；搜索仍覆盖原始进程字段，旧 `snapshot` 和桌面状态接口保持兼容。手动刷新及结束操作仍重新采样并核对完整身份，摘要缓存不用于授权终止。
- **内存足迹（默认排序）**通过 `proc_pid_rusage` 的 `ri_phys_footprint` 读取，包含脏页、压缩与换出等系统记账，更接近活动监视器的应用负担；同时单列保留 **RSS（当前常驻内存）**。二者口径不同，不能相加，不是“RSS + 全系统交换空间”，也不表示结束后必然释放的大小。应用合计按 PID 去重，缺项明确标注，不可读取时显示 `—`。菜单栏与卡片使用内存足迹，卡片另显示 RSS。
- CPU 使用两次采样间的累计 CPU 时间差，单核 100%，多核可超过 100%。首次或没有足够间隔时显示采样中。系统同时显示物理内存、交换使用量和系统报告的内存压力；无权限/不支持时显示未知。
- 应用包路径优先归组，嵌套 Helper 包归入外层应用。应用外程序的同 UID 父链或责任进程仅作为来源线索，保持独立任务，不进入来源应用的合计与操作范围。终端任务按实际父链、进程组和启动身份拆开；其他独立程序按可执行文件、工作目录和 UID 归组。无法识别的进程保留原名。
- 外部 Node.js 运行时额外根据入口脚本、工作目录和 `package.json` 的名称关联项目或工具，直接显示「brc-web」「codex-with-chatgpt」等项目名称，Node.js 运行时信息保留在归组依据和进程详情中。项目内的 Umi、Tailwind 等依赖工作进程归入项目；入口脚本属于另一个工具时优先按该工具的清单识别。不同实际目录中的同名项目保持独立。仅能取得工作目录时明确标为推断；详情保留原始进程名并展示项目目录、入口脚本和识别依据，不执行项目脚本。
- 应用和项目排行保留合计，启动实例按同组内可核对的父进程链区分，以根进程的完整身份（PID、启动时间、UID、可执行文件）生成实例 ID。同一 shell 下独立启动的两个相同项目保持两个实例；相同目录或名称不会成为合并停止范围的依据。WebKit 可使用已校验的责任进程关系，父进程已退出的后台进程可能单独列出。卡片显示实例数量，详情的「启动实例」列出根 PID、启动时间和各自占用。
- WebKit 系统托管进程在父进程链无法归属时，额外使用 macOS 的责任进程信息。只接受同 UID、当前采样中存在且读取前后完整身份一致的应用进程；归属后进入应用合计，每个 PID 仍只计一次。未取得可靠归属的 WebKit 进程单独保留，不按相同可执行路径合并不同应用。此可选系统 SPI 缺失时降级为未确定，不改变原有结束保护。
- 应用名称和 PNG 图标复用宿主的应用扫描索引、包信息读取和图标缓存；只按完整应用包路径或规范化后的同一路径匹配，不凭同名关联。输入法等未包含在启动器索引目录内的应用，按其实际 `.app` 路径读取本地化名称、bundle ID 和图标，无需逐个维护别名。排行、详情和卡片展示真实应用图标；无法读取时保留原名与首字母。`mds`、`mds_stores` 显示 Spotlight 搜索索引用途，不冒充独立应用。
- 当前用户的后台应用若无法读取可执行路径，可用同一 PID 的 macOS 应用登记核对 bundle URL 和入口位置，再按嵌套应用包路径关联外层应用，例如 WPS 登录辅助程序。原始路径仍保持不可读取，结束保护与独立实例边界继续生效。Python、PostgreSQL、MySQL、tmux、ADB 和 Redis 等命令行工具根据可执行文件路径显示随插件打包的工具标识，原生应用图标优先；素材来源见 `src/icons/README.md`。
- 对当前用户无法读取 BSD 身份信息、但仍可读取可执行路径的进程，保留为受保护的系统分组条目；仅展示名称和路径，内存、CPU、启动时间和父进程显示不可读取，不允许结束。读取不到路径的进程仍无法可靠命名。
- 可选系统级服务每次提供完整只读进程快照；宿主只有在已安装插件声明 `system-process-monitor` 能力后才允许状态、启用或停用请求。采集器和配置安装在 root 管理的 `/Library/PrivilegedHelperTools/cn.ac.camellia.flowhub.resource-monitor/daemon` 和 `/Library/LaunchDaemons/cn.ac.camellia.flowhub.resource-monitor.plist`。安装前在 root 管理的临时目录中核对授权前计算的 SHA-256 和代码签名；应用更新后提示授权更新采集器。Unix socket 只接受当前控制台用户的快照和健康检查请求，客户端核对服务端为 root，请求有大小及读写时限。root 仍可能无法读取 macOS 保护的个别字段。服务不可用时，继续显示当前用户能读取的数据，并将受限进程标为受保护。
- Android SDK 的 QEMU 模拟器独立归组，可显示虚拟设备名；其他 QEMU 仅标为虚拟机，不猜测管理工具。来源详情显示路径、工作目录、当前父进程、启动时间和用户 UID。父进程是当前关系，进程重新托管或父进程退出会影响归属，不能据此确定启动对话、是否闲置或是否可以安全停止。
- Codex 显示带对话标记的工作子进程合计，Arc 显示任务管理器报告的标签进程；不提供逐对话完整内存或 QQ 单个聊天的精确内存，不分摊共享界面、GPU 和服务。共享 PID 明确标记，各标签显示的相同进程占用不能相加。
- 原始 argv 仅在采样期间瞬时解析白名单 `-avd`、`--type` 和外部 Node 的首个入口脚本路径，不返回/保存完整命令行、后续脚本参数或内联代码。Node 项目清单最多读取 128 KiB，只保留项目名称；读取入口前后核对完整进程身份并清空临时缓冲。用户读取 Codex 关联时，另对同 UID、Codex 进程树中的非受保护工作进程瞬时解析唯一的 UUID 环境字段 `CODEX_THREAD_ID`；其他环境字段不导出。状态缓存只含不透明应用 ID、名称、应用包路径（用于匹配图标）、计数和指标，不含 PID、进程可执行路径、项目目录、入口脚本或标题。所有数据只在插件内存中，不记录活动历史。

## 手动清理

多实例汇总行提供「选择实例」，在实例表中使用「结束实例」；单实例行可直接准备该实例的确认。后端拒绝未选择实例的多实例分组终止请求，旧界面或直接调用也不能整组结束。进程行「结束」只处理该 PID 的完整身份。确认弹窗列出实例根 PID 和目标进程，默认发送 SIGTERM，可显式打开「强制结束」切换为 SIGKILL；升级保留原令牌和目标，不扩大范围，仍需通过保护与身份复核。结束渲染进程可能影响同一实例内的多个页面。

详情中的正常退出通过 macOS `NSRunningApplication.terminate()` 请求选中实例的主应用退出，可能出现应用自身的保存提示；多个界面实例必须先选择，后端不会一次退出同应用的所有实例。需要确认，并重新核对所选实例、主应用 PID、启动时间、UID 和应用包路径，确认 30 秒失效且只能使用一次。后台服务可能继续运行。主应用已退出、只剩后台服务时显示说明；FlowHub 自身、宿主及系统常驻服务不提供此入口。右下角「关闭详情」只关闭弹窗。

Chrome 等 Chromium 应用使用 `code_sign_clone` 临时副本时，以同一 PID 的 macOS 应用登记、bundle ID 及精确的副本路径校验归属，进程详情仍保留实际路径。应用名合计与退出实例分开处理，执行前重新校验所选实例。无界面或后台模式主程序不会参与应用级退出，并显示对应说明。

点击应用名打开固定尺寸的详情弹窗。刷新仅替换同一身份进程的数值，保持行顺序与分页；新进程追加，消失的进程留在原位置；全局仍存活但转到其他分组时标为“已移到其他分组”并禁用旧行操作，真正退出才标为已退出。PID 被复用时保留旧行、新增新身份，不替换用户正在查看的行。点击进程名可打开来源弹窗。

## 页面名称与跳转

详情中的「打开应用」激活所属应用。「页面与对话」仅在用户点击读取时取得标题和关联，标题不进入菜单栏缓存或磁盘历史。关联占用随常规进程采样刷新，映射五分钟失效；新任务、新标签、页面导航后需重新读取关联。未关联显示 `—`，不表示零占用或对话未运行。列表按关联状态初次排序，数值刷新不重排；支持标题、目录、PID 搜索和只看已关联。

- **Arc 标签与跳转**：通过本机 AppleScript 接口批量读取最多 500 个普通窗口标签，跳过隐私窗口；“打开”选择原标签并激活 Arc，不重新打开 URL。使用 AppleScriptObjC JSON 编码保留标题中的引号、换行与 Unicode；避开 JXA 的 `-1700` 属性转换错误。失败按权限、超时、类型转换和目标变化区分，不回显原始脚本与标题。
- **Arc 任务进程**：“读取 Arc 任务管理器”使用原生 Accessibility API 读取 Arc 自己的任务表；若未打开则尝试调用 Arc 自带的 Open Task Manager 菜单命令，也可手动从 Help → Troubleshooting 打开。未授权、窗口关闭、表格未就绪、未显示 PID 列分别提示。只读取当前可访问行，受任务管理器筛选、滚动位置和布局影响，界面显示当前读取范围；不自动滚动用户窗口。仅将显式标签任务、普通窗口已知标题及经核对的 PID/启动时间关联；不把子框架、扩展或未知/隐私标题绑定到普通标签。同名标签保留任务 PID 占用、禁用歧义跳转。缓存进程身份与当前采样身份不一致时拒绝关联；同 PID 多标签标记共享。不安装浏览器扩展，不启用 JavaScript from Apple Events 或远程调试端口。
- **Codex 对话工作进程**：只读 `$CODEX_HOME`（或 `~/.codex`）最高版本的 `state_*.sqlite` 中最近 100 个未归档、有用户消息的对话，只查询 ID、标题和项目目录；再按当前工作进程的 `CODEX_THREAD_ID` UUID 关联，可补充最多 100 个不在近期索引中的已识别对话。进程树只用于限制读取范围，不能代替 ID 证据。不安装 Hook、不连接或重启 Codex app-server，不读取消息正文，不将共享主进程、渲染器、GPU 或 app-server 分配给对话。未继承标记、身份变化、重托管或权限不足的进程保留未关联状态。通过已安装 Codex 的 `codex://threads/<UUID>` 跳转；索引/环境标记/链接属于本机版本适配，变更时会降级或明确报错。
- “进程”打开关联进程弹窗，可查看来源或逐个结束；进程详情页也显示已读取的页面名称，并可只看未关联进程。每个关联只引用完整身份，不复制或累加旧指标；PID 被复用不会将新进程计入旧关联。跨应用单列的 Codex 工作子进程也可出现在对话详情，不能再与应用排行相加。
- 跳转使用后端生成、绑定应用且 5 分钟有效的随机令牌，重新读取应用分组并核对令牌；前端不能提交任意 URL、脚本或应用路径。Arc 调用限时 15 秒，对话数据库只读并设置短锁等待，失败可重试。

清理分为 `terminate_preview` / `terminate_confirm`：预览重新采样，生成绑定所选实例、30 秒有效且只能使用一次的随机令牌；确认重新核对 PID、微秒启动时间、UID、可执行路径和该实例的目标集合。该实例增加子进程、身份变化、过期或没有显式确认时拒绝；另一个实例的启动不会扩大本次范围。发送每个信号前再次校验身份，已经随根进程正常退出的子进程无需再次发送信号。macOS 此处使用 PID 信号接口，不能保证检查与信号原子化。

禁止结束系统核心路径、其他 UID、路径不可核实的进程、插件自身、FlowHub 及插件当前祖先进程。选中实例含受保护进程时禁止整实例结束，仍可逐个操作允许的成员。单次最多 256 个进程。执行后分别显示信号是否发送、进程是否观察到退出和失败原因，SIGTERM 后仍存活的进程显示等待退出。采集失败保留旧数据与错误，超过 20 秒显示过期；清理始终先重新读取真实进程。
