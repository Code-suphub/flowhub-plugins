# 2FA 生成器与 URI 导入验收

目标：`twofa 0.5.0`。0.2.0 接入 [totp-rs](https://github.com/constantoine/totp-rs) 的生成器及 URI 解析；0.3.0 参考 [Proton Authenticator](https://proton.me/authenticator) 的账户卡片组织，自行使用公共组件实现，未复制其源码或素材。兼容基线为原插件的加密存储与 SHA1／6 位／30 秒账户。宿主安装与原生 WebKit 验收不继承后台浏览器结果。

## 0.2.0 基线检查

- [x] Rust 7 项测试通过，包含 RFC 6238 附录 B 的三种算法、六个时间点，前导零、倒计时、旧 JSON 默认参数、旧加密文件、不改写读取、原有短密钥及分隔符。
- [x] URI 预览仅返回元数据且不创建文件；保存后加密、权限 600，同名导入／创建拒绝且原文件不变。编辑空密钥保留原生成参数，列表和错误不回显密钥。
- [x] 不支持类型／参数、重复参数、冲突发行方、畸形编码、超长输入和控制字符被拒绝；无效周期／位数不能进入生成器造成 panic。
- [x] TypeScript 与 20 项前端／契约测试通过；覆盖分步确认、重名改名、取消与迟到响应、解析／保存失败保留草稿、重复提交、IME／长按回车、八位展示与原始数字复制、旧 RPC 兼容及只读预览。
- [x] 独立包构建和资源检查通过：代码／样式在包内，没有旧入口、CDN 或内联可执行脚本；版本三处为 0.2.0。
- [x] 新依赖 totp-rs 6.0.0 的 MIT 版权与许可随独立包保留在 `ui/licenses/totp-rs.txt`。
- [x] 插件仓库 `npm run build` 完整通过；`npm run layout:machines -- --check` 的所有视图和断点通过。完整回归依赖构建后的机器可执行文件，先构建再测试。
- [x] 插件仓库 `npm test` 完整通过，覆盖公共资源和六个插件。首次全量发现测试临时目录并行命名碰撞，使用进程内唯一序号修正后，2FA 专项及完整回归均通过。
- [x] 后台页面连接真实插件后端，数据目录独立且只使用公开测试密钥；实际完成解析错误、预览、重名提示、改名保存、搜索及八位生成，旧测试账户保持。取消不新增账户并返回触发按钮。
- [x] 860 × 600 浅色、640 × 360／380 × 600 深色检查，矮窗正文可滚动、底部操作可达，窄窗无横向溢出；独立只读预览仅解析示例并禁用导入，控制台没有错误／警告。截图与原始记录位于仓库外。

## 安装版检查

- [x] 在 FlowHub 中更新并重新加载 twofa 0.5.0，核对安装清单和构建目录，保持启用及原数据目录；3 个原账户可读，安装前后加密文件／本地密钥哈希一致，真实密钥不输出。
- [ ] 使用独立测试账户在真实 WebKit 中完成 URI 解析、取消、改名导入、刷新／重开持久化和编辑空密钥；通过启动器 `2fa 名称` 找到测试项，明确执行后得到相应位数的验证码。
- [ ] 真实中文输入法、Escape、Tab、重新唤出、最小窗口与双屏检查；关闭／保存后焦点不落到后台应用。
- [ ] 复制测试验证码到专用空白接收窗口核对连续数字，不向真实登录、聊天或终端写入；测试结束恢复原剪贴板，仅清理自建测试账户。

本轮后台验证没有读取真实密钥、写入用户账户数据或操作系统剪贴板。0.3.0 时图片识别、摄像头扫码、批量迁移和导出均未实现；图片导入现已推进到下述 0.4.0。

## 0.4.0 二维码图片导入（2026-11-06）

- [x] 本机 File API／Canvas 解码 PNG、JPEG，打包 jsQR 1.4.0（Apache-2.0）及许可，不新增摄像头、网络或宿主文件系统权限；格式、8 MiB、边长／像素总量检查先于图片解码，识别按最长边 1600 像素限制。
- [x] 图片识别后调用原有 `preview_import`，核对元数据后再确认加密保存；失败、取消、同名改名、重复提交、只读模式与原有 URI 导入共用流程。图片和 URI 不写浏览器存储，不上传，错误不回显识别内容。
- [x] Rust 7 项、前端／契约 25 项、类型及独立包构建通过；真实二维码像素覆盖正色、反色、非 TOTP、无二维码及尺寸／格式边界，DOM 覆盖图片预览后改名确认、无效图片、只读禁用。
- [x] 后台浏览器加载真实构建、真实插件和临时独立数据目录，以公开 RFC 测试密钥生成的 PNG 完成选择文件→预览→取消不新增→再次识别→改名确认→刷新持久化。严格 CSP 保持 connect-src none、img-src self data；没有读取真实账户或使用系统剪贴板。
- [x] 1280 × 720 浅色及 380 × 600 深色检查；窄窗弹窗 342 × 568，页面宽度 380，无横向溢出，操作区可达。截图在仓库外 `plugin-comparison/twofa-qr-preview-*.png`。
- [x] 与 Docker 一并完成插件仓库全量构建、完整测试和机器布局检查；MIME 识别按文件签名修正后，2FA 专项及独立构建再次通过。宿主应用检查通过，根目录仍是既有 198.18.0.1 断言失败。
- [ ] 安装检查已由 0.5.0 完成；真实 WebKit 的系统文件选择、PNG／JPEG、中文命名、取消焦点、最小窗口和双屏继续待验，不能继承 Chromium 或 DOM 模拟结果。

这里只读取单个二维码，不支持相机扫码、整页多码自动分拣、Google Authenticator 迁移码或批量账户迁移。公开图片与本机测试目录由 `node tests/qr-browser-smoke.mjs` 创建，退出时只清理其自建目录。
