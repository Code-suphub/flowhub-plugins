## 正式版发现与补修

0.3.0 中，真实指针打开详情后，原生 Tab 依次到“复制摘要”“相关事件”，再按 Tab 会离开 iframe，焦点进入宿主页；此时 Esc 未关闭详情。这与先前 Chrome 预览中的原生 dialog 行为不同，不能凭浏览器检查宣布实机通过。

0.3.1 在公共 `DialogShell` 中显式处理 Tab／Shift+Tab 的首尾循环，跳过禁用、隐藏及 inert 控件，保留调用方的键盘处理和嵌套弹窗边界；仅在本轮外设中心构建包中发布。另去除 WebKit 对未选中导航按钮应用的默认灰底。正式版复测：三个 Tab 回到“关闭”，Shift+Tab 回到“相关事件”，Esc 能关闭。

随后真实指针复核发现 WebKit 点击卡片时没有把卡片设为活动控件，关闭后回到设备区域。0.3.2 在打开详情前显式聚焦被点击卡片；浏览器用“不预先聚焦的 click”复现这一前提，再断言关闭后返回卡片，避免测试助手自动聚焦掩盖问题。

## CLI 能验证什么

1. 普通 shell 可以核对注册版本、目录、包指纹、正式宿主与插件进程的父子关系；后端 RPC 及构建检查可在后台执行。
2. `toolkit desktop huashu mac` 可以读取正常安装版的原生窗口／AX，截取窗口，并通过 `op` 发起真实指针输入；本次供电和详情入口均实际生效。此类操作仍使用系统桌面，不能与其他会话的键鼠操作保证互不干扰。
3. 每次操作必须读回页面状态。差分结果 `confirmed` 不说明业务正确，`suspected_noop` 也可能误判：本次“供电”被误判，但 AX 的选中页和截图证明切换成功。截图可能包含同应用的父窗口，不能直接按其整体尺寸换算目标窗口坐标。
4. `flowhub-ui-test.mjs` 只驱动独立测试二进制；其 synthetic-dom 回归不等于正常安装版、真实键盘或输入法验收。旧 `flowhub-cli.mjs` 也没有正式插件安装或原生按钮控制能力。
5. 锁屏后不能验证原生交互。本轮锁屏后遇到目录框只可截图、AX 控件树失效；用户解锁后，目录框的自动输入仍不稳定，不能确定锁屏是根因。用户手动点 Open 后，后续更新确认和管理页操作恢复正常。CLI 搜索曾超时，但读回已经正确筛选；没有重放输入或把退出码当作业务成功。
