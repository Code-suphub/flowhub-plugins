# 外设中心 CLI 和 K75 验收

目标包为外设中心 0.3.15。

| 项目 | 验收方式 | 判据 |
| --- | --- | --- |
| 构建与协议 | 插件仓库测试与外设中心构建 | Rust、类型检查、行为测试、包内资源和 CSP 检查通过 |
| 缓存一致性 | 隔离启动打包后端，经 CLI 调用 `status`、`refresh`，再读 stdin 的 `status_snapshot` | PID 一致，刷新后的时间戳与宿主通道读取一致，数据未过期 |
| 权限与异常 | 核对 CLI 子目录与 socket 权限，验证非法命令、插件停止与重启 | 目录 0700、socket 0600；非法命令失败，停止后客户端失败，重启后恢复 |
| Mac mini 正式安装版 | 使用插件市场更新，核对注册版本与进程路径，从 MacBook 通过 SSH 调用 | 后端是 FlowHub 子进程，三个命令的 PID 和版本一致 |
| K75 有线读取 | 连接 USB ID 为 `258a:0112` 的标准 K75 RGB | 读到设备版本，厂商配置回包长度与标记通过校验，电源返回两个原始字节 |
| Win／Mac 模式读取 | 用实体快捷键切换，在同一把键盘上连续读取厂商配置 | `0x4023` 配置首字节在 Mac、Win、Mac 三次读取中为 1、0、1 |
| 灯光和模式写入 | 对照工程版实机写入，比较同一设备前后回包 | 确认具体命令、状态读回与恢复方式后再开放 |

Mac mini 隔离验收已通过缓存一致性、socket 权限和 K75 有线读取。版本为 0.3.15，USB 设备版本为 `0x4023`，配置块为 128 字节。隔离验收使用单独数据目录，通过 MacBook 上的 Toolkit SSH 发起。租约测试覆盖运行中端点保护、停止后连接失败和重启后恢复。

正式安装经插件市场完成。核对了注册版本、后端与 K75 helper 的文件指纹、插件启用状态，以及其他插件的注册信息。MacBook 经 SSH 调用 `status`、`refresh`、`k75 status`，三条命令均由同一个 FlowHub 子进程处理。刷新得到 7 个 USB、2 个蓝牙、2 个显示器，安装版设备页也显示相同数量。K75 最后一次返回 `osMode: mac`。灯效和模式写入待验证。
